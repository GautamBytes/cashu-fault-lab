# Cashu Fault Lab v0.2.0 Release Evidence Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish Cashu Fault Lab v0.2.0, prove the installed npm package in Docker, and replace the landing page's v0.1.4 sample with redacted first-party v0.2.0 evidence and screenshots.

**Architecture:** Use a release-preparation pull request before tagging, because the tag workflow publishes the npm package and runtime images. After publication, execute the registry package from a clean temporary directory, retain only sanitized evidence, and deliver that evidence through a second website pull request.

**Tech Stack:** Node.js 24, pnpm 11, TypeScript, Next.js, Vitest, Playwright, Docker Compose, GitHub Actions, npm provenance.

## Global Constraints

- Keep historical v0.1.x release notes and artifacts immutable.
- Treat `apps/npm-cli/package.json` as the public release version; private workspace packages remain version 0.1.0.
- Use only `npx --yes cashu-fault-lab@0.2.0 demo` for shipped-package evidence.
- Use disposable loopback-only Docker infrastructure and no production keys, tokens, wallets, or funds.
- Label retained results `First-party reproducible evidence`, never certification or independent validation.
- Do not create, move, or recreate the v0.2.0 tag after publication starts.
- Never retain proof secrets, wallet private keys, bearer tokens, invoices, raw Cashu tokens, or ciphertext.

# v0.1.4 maintainer-preview checklist

## Release requirements

- [x] The npm package installs outside the monorepo on Node.js 24.
- [x] `adapter init`, `adapter preflight`, and `adapter preview` remain aligned with the current
      package version and loopback-only safety model.
- [x] `adapter preflight` validates the capability contract, profile support, and configured
      read-only evidence endpoints with stable diagnostics.
- [x] The wallet lifecycle HTTP surface is opt-in and requires durable state plus bearer
      authentication.
- [x] cashu-ts and CDK lifecycle adapters run funded `mint`, `swap`, `send`, `receive`, `restore`,
      and `reconcile` lanes against pinned Nutshell and mintd mints.
- [x] cashu-ts and CDK melt recovery use an authenticated Lightning settlement probe before
      treating a paid quote as terminal evidence.
- [x] Lifecycle reports redact raw seeds, tokens, invoices, proof secrets, and wallet keys.
- [x] The NIP-60 wallet doctor collects read-only multi-relay state, drops proof secrets at capture,
      never publishes events, and never moves value.
- [x] Wallet-doctor diagnosis codes and dry-run repair plans are oracle-checked; the capture bundle
      is the external CI interop contract.
- [x] The funded wallet-doctor lane (`pnpm test:doctor:funded`) passes packaged scenarios against a
      real mint, two fault relays, and the lab reference fixture.
- [x] The manual release gate includes funded lifecycle, Lightning-regtest lifecycle, and funded
      wallet-doctor lanes.
- [x] Published runtime images and the npm package are built through GitHub Actions.
- [x] npm provenance binds v0.1.4 to the tagged source commit and publishing workflow.
- [x] Documentation describes lifecycle, doctor, and adapter results as diagnostic evidence, not
      certification.

## External validation blockers

- [ ] Integrate an independent wallet receiver maintained outside this repository.
- [ ] Obtain hands-on feedback from external Cashu wallet maintainers.
- [ ] Operate independent read-only ledger, mint, and Lightning evidence authorities for qualifying
      wallets.
- [ ] Run at least two qualifying implementation pairs against two distinct mint identities.
- [ ] Independently reproduce or verify source and build provenance for qualifying adapter images.
- [ ] Complete public-relay Nostr hardening and independent interoperability review.
- [ ] Exercise wallet-doctor `check` against capture bundles produced by wallets outside this
      repository.

Unchecked items do not block use of the v0.1.4 maintainer preview. They block certification and
strong interoperability or funding claims until external evidence exists.
